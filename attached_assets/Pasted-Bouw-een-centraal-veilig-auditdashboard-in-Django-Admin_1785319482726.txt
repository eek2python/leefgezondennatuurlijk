Bouw een centraal, veilig auditdashboard in Django Admin waarin bestaande en
toekomstige productaudits kunnen worden uitgevoerd en bekeken.

Aanleiding:

In het project bestaan inmiddels meerdere audits, managementcommands, helpers
en tests voor onder andere:

- productdata;
- productvarianten;
- displayvariantconsistentie;
- affiliate-links;
- prijzen;
- prijsniveaus;
- beschikbaarheid;
- afbeeldingen;
- JSON-LD;
- rankings en awards;
- ontbrekende of inconsistente velden.

Deze controles moeten centraal beschikbaar worden gemaakt via Django Admin,
zonder bestaande auditlogica te dupliceren.

Belangrijk:

- inspecteer eerst de huidige setup;
- hergebruik bestaande auditfuncties en managementcommands;
- audits zijn standaard read-only;
- wijzig geen productdata vanuit het dashboard;
- voer geen automatische reparaties uit;
- beperk toegang tot bevoegde beheerders;
- voorkom dubbele auditimplementaties;
- zorg dat normale adminpagina’s blijven werken.

3. CENTRAAL AUDITRESULTAAT
==================================================

Gebruik één gestructureerd resultaatmodel of dataclass, bijvoorbeeld:

@dataclass
class AuditIssue:
    code: str
    severity: str
    message: str
    category: str | None = None
    product_slug: str | None = None
    variant_id: str | None = None
    file_path: str | None = None
    field: str | None = None
    expected: str | None = None
    actual: str | None = None

@dataclass
class AuditResult:
    audit_key: str
    title: str
    started_at: datetime
    finished_at: datetime
    status: str
    issues: list[AuditIssue]
    metadata: dict

Gebruik bestaande projectconventies als die al aanwezig zijn.

Ondersteun severities:

- info;
- warning;
- error;
- critical.

Ondersteun uitvoeringsstatussen:

- pending;
- running;
- completed;
- failed.

==================================================
8. UITVOEREN VAN EEN AUDIT
==================================================

Een auditstart moet via POST verlopen.

Vereisten:

- CSRF-bescherming;
- admin login vereist;
- geschikte permissie vereist;
- geen uitvoering via GET;
- valideer audit key;
- valideer categorie;
- log wie de audit startte;
- voorkom onbedoeld dubbel starten van dezelfde audit;
- toon een duidelijke succes- of foutmelding.

Gebruik een formulier met:

- audit;
- categorie, indien ondersteund;
- eventueel `strict`;
- eventueel `network_checks`.

Standaard:

- `strict=False`;
- `network_checks=False`;
- read-only.

==================================================
9. SYNCHROON OF ACHTERGRONDTAAK
==================================================

Controleer eerst of het project achtergrondtaakinfrastructuur heeft.

Wanneer Celery, RQ, Huey of een gelijkwaardige bestaande oplossing aanwezig is:

- voer lange audits als achtergrondtaak uit;
- sla status en voortgang op;
- laat de adminpagina periodiek verversen of bied handmatige refresh.

Wanneer geen achtergrondinfrastructuur bestaat:

- voeg niet uitsluitend hiervoor een zwaar jobsysteem toe;
- voer snelle, lokale audits synchroon uit;
- markeer langzame of netwerkafhankelijke audits als niet geschikt voor directe adminuitvoering;
- bied voor die audits een commandline-instructie of beperkte veilige uitvoering;
- voorkom request time-outs.

Classificeer audits bijvoorbeeld als:

- quick;
- standard;
- long_running;
- network_dependent.
