Build a reusable, production-ready product image processing pipeline for my existing Django affiliate website.

The website is called “Leef Natuurlijk & Gezond” and contains product images for categories such as:

- ceramic frying pans;
- stainless-steel frying pans;
- sauté pans;
- woks;
- air fryers;
- wooden cutting boards;
- glass food-storage containers.

The pipeline must standardize product images so that product cards look consistent, images load quickly and original source files are always preserved.

Do not build the Django admin upload interface yet. However, structure the implementation so that a future custom admin page can call the same image-processing service without duplicating logic.

6. FILE-NAMING RULES
==================================================

Output file names must be derived from the explicit manifest slug.

Normalize slugs safely:

- lowercase;
- replace spaces and underscores with hyphens;
- remove unsupported punctuation;
- transliterate accented characters where practical;
- collapse repeated hyphens;
- remove leading and trailing hyphens.

Examples:

“GreenPan Bistro XL” becomes:

greenpan-bistro-xl.webp

“Igluu Meal Prep – Rond” becomes:

igluu-meal-prep-rond.webp

Do not silently overwrite two images that produce the same output filename.

Raise a manifest validation error before processing when duplicate output paths exist.

==================================================
7. IMAGE-PROCESSING STEPS
==================================================

Implement the processing in this order.

Step 1: Open the source safely

- use Pillow;
- handle corrupt or unreadable files;
- use ImageOps.exif_transpose to apply EXIF orientation;
- close file handles properly;
- never modify the original source file.

Step 2: Normalize the working image

- convert to RGBA while processing;
- preserve transparency until the final canvas is created;
- do not preserve unnecessary source metadata.

Step 3: Detect removable outside space

Automatic cropping must be conservative.

For images with transparency:

- use the alpha channel to detect the visible bounding box;
- remove only fully or almost fully transparent outside space.

For images without transparency:

- inspect pixels along the outer border;
- estimate whether the border has a sufficiently uniform light background;
- only crop when the border is demonstrably uniform and light;
- compare pixels with the estimated background colour using a configurable tolerance.

Do not blindly treat every near-white pixel in the image as background.

Do not remove white parts of the actual product.

If the background is not sufficiently uniform or light:

- skip automatic cropping;
- preserve the complete source image;
- add a warning to the processing report.

If no valid bounding box is found:

- keep the original image;
- add a warning;
- do not crash.

Allow `auto_crop: false` as a manifest override.

Step 4: Preserve a small safety margin

After automatic cropping, retain or add a small internal safety margin so that the product does not touch the calculated bounding box.

Step 5: Calculate the target content area

For an 800 × 800 canvas and a fill ratio of 0.78, the product must fit within:

624 × 624 pixels

Preserve the source aspect ratio.

Do not stretch or distort images.

Step 6: Resize

Use:

Image.Resampling.LANCZOS

Rules:

- reduce large images as needed;
- allow limited upscaling only up to MAX_UPSCALE_FACTOR;
- never upscale without limit;
- generate a warning when the source is too small to reach the preferred display size;
- record original, cropped and final dimensions.

Step 7: Position the product

Place the resized image on a square canvas.

Default:

- horizontally centred;
- vertically centred;
- white background.

Support optional manifest overrides:

- horizontal_offset;
- vertical_offset.

Offsets must be bounded so that the image cannot accidentally be placed entirely outside the canvas.

Step 8: Flatten transparency

Composite the working RGBA image onto the configured background.

Convert the final image to RGB before saving as lossy WebP.

Step 9: Save as WebP

Use:

- format: WEBP;
- quality: 85;
- method: 6;
- optimized output where supported;
- no EXIF or unnecessary metadata.

Write files atomically:

- first save to a temporary output file;
- replace the final output only after successful completion;
- remove abandoned temporary files after errors.

==================================================
8. CHANGE DETECTION
==================================================

Avoid reprocessing unchanged files unnecessarily.

Calculate and store sufficient information in the report, such as:

- source path;
- source checksum;
- processing configuration checksum;
- output path;
- processing timestamp.

When the source file and relevant configuration have not changed and the output exists:

- skip it by default;
- report the status as `unchanged`.

The `--force` option must process it again.

A change to a relevant configuration value must cause reprocessing.

==================================================
9. MANAGEMENT COMMAND
==================================================

Create a Django management command:

python manage.py process_product_images

Support:

python manage.py process_product_images --all

Processes all enabled manifest entries.

python manage.py process_product_images --category vershoudbakjes

Processes one category.

python manage.py process_product_images --product igluu_meal_prep_3delig

Processes one product family.

python manage.py process_product_images --source vershoudbakjes/example.jpg

Processes one matching manifest entry.

python manage.py process_product_images --dry-run

Validates and shows intended actions without writing files.

python manage.py process_product_images --force

Reprocesses files even when unchanged.

python manage.py process_product_images --check

Only validates the manifest, original files and existing processed images.

python manage.py process_product_images --report

Writes a detailed JSON report.

Allow compatible options to be combined, for example:

python manage.py process_product_images \
    --category vershoudbakjes \
    --force \
    --report

Prevent ambiguous combinations where necessary and show a clear command error.
