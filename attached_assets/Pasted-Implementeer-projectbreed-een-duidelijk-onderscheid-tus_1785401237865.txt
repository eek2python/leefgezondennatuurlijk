Implementeer projectbreed een duidelijk onderscheid tussen affiliate-, retailer- en fabrikantlinks voor alle productkaarten, vergelijkingstabellen, productdetailpagina’s en varianten.

DOEL

Gebruik voortaan drie afzonderlijke URL-velden:

affiliate_url

Alleen voor aantoonbare affiliatelinks.

Publieke links krijgen:rel="nofollow sponsored noopener"

retailer_url

Voor normale productpagina’s bij webwinkels zonder actieve affiliatecode.

Publieke links krijgen:rel="nofollow noopener"

Gebruik nooit rel="sponsored".

official_url

Voor informatieve productpagina’s van de fabrikant.

Publieke links krijgen:rel="noopener"

Gebruik nooit rel="sponsored".

Presenteer deze niet als kooplink of prijslink.

Hanteer overal deze prioriteitsvolgorde:

affiliate_url→ retailer_url→ official_url→ availability_label→ anders geen knop of link tonen

BELANGRIJKE RANDVOORWAARDEN

Inventariseer eerst hoe productlinks momenteel worden opgebouwd.

Zoek naar bestaande helpers zoals:

resolve_commercial_fields

resolve_variant_fields

display_variant

set_display_variant

affiliate_url-resolvers

Breid bestaande centrale helpers uit in plaats van parallelle linklogica toe te voegen.

Voorkom dat templates rechtstreeks een willekeurig URL-veld kiezen.

Houd de bestaande variantselectie intact.

Voorkom fallback van een geselecteerde variant naar een link van een andere variant.

Verander geen bestaande URL inhoudelijk tijdens deze taak.

Verplaats bestaande links niet automatisch van affiliate_url naar retailer_url, omdat niet technisch kan worden vastgesteld of een URL werkelijk een actieve affiliatelink is.

Rapporteer bestaande verdachte affiliate_url-waarden wel voor handmatige beoordeling.

Verwijder geen trackingparameters uit echte affiliatelinks.

Pas geen productprijzen, beoordelingen, teksten, awards of rangschikkingen aan.

FASE 2 — DATASTRUCTUUR UITBREIDEN

Ondersteun bij elk product en iedere variant optioneel:

"affiliate_url": "",
"retailer_url": "",
"official_url": "",
"availability_label": "",

Alle velden moeten optioneel zijn. Oude producten die alleen affiliate_url hebben, mogen niet breken.

Gebruik bij voorkeur lege strings of None volgens de bestaande projectconventie. Normaliseer alleen tijdens resolutie, bijvoorbeeld:

def normalize_optional_url(value):
    if not isinstance(value, str):
        return ""
    return value.strip()

Voeg geen databasevelden of migraties toe wanneer de producten momenteel vanuit Python-dictionaries worden geladen.

FASE 3 — CENTRALE LINKRESOLVER

Maak of breid één centrale helper uit, bijvoorbeeld in:

utils/variant_helpers.py

Gebruik een gestructureerd resultaat, bijvoorbeeld:

from dataclasses import dataclass


@dataclass(frozen=True)
class ProductLink:
    url: str = ""
    link_type: str = ""
    label: str = ""
    rel: str = ""
    is_commercial: bool = False

Ondersteunde linktypen:

affiliate
retailer
official
none

Voorgestelde resolver:

def resolve_product_link(product, selected_variant=None):
    source = selected_variant or product

    affiliate_url = normalize_optional_url(source.get("affiliate_url"))
    retailer_url = normalize_optional_url(source.get("retailer_url"))
    official_url = normalize_optional_url(source.get("official_url"))

    if affiliate_url:
        return ProductLink(
            url=affiliate_url,
            link_type="affiliate",
            label="Bekijk actuele prijs",
            rel="nofollow sponsored noopener",
            is_commercial=True,
        )

    if retailer_url:
        return ProductLink(
            url=retailer_url,
            link_type="retailer",
            label="Bekijk actuele prijs",
            rel="nofollow noopener",
            is_commercial=True,
        )

    if official_url:
        return ProductLink(
            url=official_url,
            link_type="official",
            label="Bekijk productspecificaties",
            rel="noopener",
            is_commercial=False,
        )

    return ProductLink()

Pas dit aan de bestaande datastructuur en codeconventies aan.

VARIANTREGELS

Wanneer een product varianten heeft:

Gebruik eerst de URL-velden van de actief geselecteerde variant.

Gebruik geen URL van een andere variant.

Productniveau-fallback mag alleen als die aantoonbaar naar de algemene productfamilie of naar dezelfde geselecteerde uitvoering leidt.

Behoud bestaande veilige variantregels uit resolve_commercial_fields.

Een lege affiliate_url op de geselecteerde variant mag niet automatisch leiden tot de affiliate_url van een andere variant.

retailer_url en official_url moeten dezelfde variantveiligheid volgen.

De link moet bij een variantwissel samen met afbeelding, prijs en beschikbaarheid veranderen.

Wanneer productniveau-fallback volgens de huidige architectuur nodig is, implementeer die expliciet en documenteer de regel. Geen impliciete dictionary-fallback.

FASE 8 — JSON-LD

Controleer bestaand Product-, Offer- en ItemList-schema.

Regels:

Gebruik een retailer_url of official_url niet automatisch als affiliate- of Offer-URL.

Een fabrikantinformatiepagina is geen verkooppagina.

Genereer geen Offer wanneer er:

geen concrete verkoopprijs is;

geen concrete verkoper is;

geen daadwerkelijke verkooppagina is;

alleen official_url beschikbaar is.

availability_label is interne/publieke presentatietekst en mag niet rechtstreeks als ongeldige schema.org-waarde worden uitgevoerd.

Gebruik alleen ondersteunde schema.org-availabilitywaarden.

Verander bestaande JSON-LD niet verder dan noodzakelijk voor correcte URL-semantiek.

Rapporteer twijfelgevallen.

ACCEPTATIECRITERIA

De taak is voltooid wanneer:

alle productweergaven dezelfde centrale linkresolver gebruiken;

affiliate_url altijd prioriteit heeft;

retailer_url tweede prioriteit heeft;

official_url alleen als informatielink wordt getoond;

availability_label wordt getoond wanneer geen link beschikbaar is;

niet-affiliatelinks nooit rel="sponsored" krijgen;

varianten nooit een verouderde of verkeerde URL overnemen;

geen lege of misleidende knoppen verschijnen;

vergelijkingstabellen dezelfde logica gebruiken;

bestaande producten achterwaarts compatibel blijven;

auditregels zijn toegevoegd;

alle nieuwe en bestaande tests slagen.

BELANGRIJKE NUANCE

Verplaats in deze taak nog niet alle bestaande affiliate_url-velden automatisch. Daarvoor moet eerst duidelijk zijn welke links werkelijk bij een actief affiliateprogramma horen. De nieuwe structuur en templatevolgorde kunnen wel direct worden ingevoerd; daarna kunnen de bestaande URL’s gecontroleerd worden geclassificeerd.
