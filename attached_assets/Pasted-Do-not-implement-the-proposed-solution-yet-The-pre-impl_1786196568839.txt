Do not implement the proposed solution yet.

The pre-implementation finding changes the architecture of this task.

The current proposal says:

> The Django Product model does not contain price, availability or price_last_checked. These values currently live in Python product data files. The implementation would add the fields to the database, but the website would continue rendering price and availability from the Python files.

This would create two sources of truth and is NOT acceptable.

If price or availability is edited in Django Admin, that change must also be reflected on the public website.

## Revised goal

Implement a safe incremental migration where:

* the existing `products/products_*.py` files can continue to contain the general/static product information;
* dynamic affiliate-maintenance fields are stored in Django/database;
* the public website reads the database values for those dynamic fields;
* existing Python values can temporarily be used as fallback during migration.

The dynamic maintenance fields are:

* `price`
* `availability`
* `price_last_checked`

Also investigate whether the effective affiliate/product URL should be database-managed or whether the existing URL architecture should remain unchanged.

Do not migrate all product content to the database as part of this task unless technically necessary.


The Python files may temporarily still contain `price` and `availability`, but these values should become fallback/initialization values rather than the authoritative runtime values.

# 5. Runtime integration

Modify the product-loading/rendering layer so that database values override the equivalent Python values.

Prefer implementing this in ONE central place rather than adding database lookups separately to many templates.

For example, if the project has a product service/helper/normalization layer, enrich each product there:

Conceptually:

```python
runtime_product["price"] = db_product.price or python_product["price"]
runtime_product["availability"] = (
    db_product.availability or python_product["availability"]
)
```

Use proper logic so valid values such as `0` are not accidentally treated as missing.

`price_last_checked` does not need to exist in the Python files.
