1. FAVICON EN APPLE TOUCH ICON
==================================================

In de productie-404-logs komen regelmatig requests voor:

/favicon.ico
/apple-touch-icon.png
/apple-touch-icon-precomposed.png

Deze requests lijken afkomstig van normale browsers/mobile devices en moeten
bij voorkeur geen 404 geven.

AUDIT

Controleer eerst:

- welke favicon/icon-bestanden al in het project aanwezig zijn;
- welke static directories worden gebruikt;
- of base.html of een centrale <head>-partial al favicon-tags bevat;
- hoe Django static files op productie worden geserveerd;
- of WhiteNoise of een vergelijkbare static-file-oplossing wordt gebruikt.

HERGEBRUIK BESTAANDE BESTANDEN

Als er al geschikte logo/favicon/icon-bestanden bestaan, gebruik die.

Maak GEEN willekeurig nieuw visueel ontwerp als er al een geschikt icoon aanwezig is.

Als er alleen een geschikt PNG/WebP-logo beschikbaar is maar geen favicon.ico,
controleer dan of het technisch verstandig en veilig is om daar een faviconvariant
van te maken.

Als hiervoor geen geschikt bronbestand bestaat, verander dan niets aan het ontwerp
maar rapporteer dat handmatig een faviconbestand moet worden aangeleverd.

GEWENSTE HTML

Zorg indien mogelijk centraal in de <head> voor correcte tags, bijvoorbeeld:

<link rel="icon" href="{% static 'images/favicon.ico' %}">
<link rel="apple-touch-icon" href="{% static 'images/apple-touch-icon.png' %}">

Gebruik de werkelijk aanwezige bestandspaden.

APPLE TOUCH ICON

Idealiter is apple-touch-icon.png minimaal 180x180 pixels.

Controleer of een geschikte afbeelding beschikbaar is.

APPLE-TOUCH-ICON-PRECOMPOSED

Moderne iOS-versies gebruiken normaal apple-touch-icon.png.

Voeg geen verouderde extra metadata toe tenzij dit zinvol is.

Als browsers nog rechtstreeks:

/apple-touch-icon-precomposed.png

opvragen, onderzoek of het eenvoudig en veilig is om hiervoor hetzelfde icoon
beschikbaar te maken.

Voorkom onnodige duplicatie als dat niet nodig is.

ROOT /favicon.ico

Browsers vragen vaak automatisch:

/favicon.ico

op, ook wanneer een <link rel="icon"> aanwezig is.

Controleer of deze root-URL na de wijziging 200 kan retourneren.

Gebruik hiervoor bij voorkeur de bestaande Django/static configuratie.

Voeg alleen een expliciete Django route voor /favicon.ico toe als dat daadwerkelijk
nodig is en technisch de nette oplossing is.

Voorkom redirect chains.

2. ONTBREKENDE RVS-AFBEELDING
==================================================

In de logs staat:

GET /static/images/rvs-koekenpannen.jpg
→ 404

User-agent:

AhrefsBot/7.0

Onderzoek projectbreed exact deze string:

rvs-koekenpannen.jpg

Zoek in:

- templates
- Python-bestanden
- CSS
- JavaScript
- JSON-LD
- OpenGraph metadata
- Twitter metadata
- sitemap/code
- oude configuratiebestanden
- tests
- static references

Bepaal daarna welke situatie van toepassing is.

SITUATIE A — URL wordt nog gebruikt

Als de website of metadata nog verwijst naar:

/static/images/rvs-koekenpannen.jpg

maar het bestand niet bestaat:

- bepaal welk bestaand beeld bedoeld is;
- controleer of bijvoorbeeld een .webp-, .png- of anders genoemde variant bestaat;
- pas de verwijzing aan naar het juiste bestaande bestand;
- verander GEEN afbeeldingen inhoudelijk;
- verander alleen de kapotte referentie.

Controleer vooral:

- og:image
- twitter:image
- <img src>
- JSON-LD image
- category thumbnails
- blog metadata

SITUATIE B — Bestand bestaat maar wordt niet goed geserveerd

Als rvs-koekenpannen.jpg wel bestaat:

- controleer static path;
- controleer {% static %};
- controleer collectstatic;
- controleer eventuele casing-problemen;
- controleer of het bestand in STATIC_ROOT terechtkomt.

Los alleen de concrete oorzaak op.

SITUATIE C — URL bestaat nergens meer

Als:

rvs-koekenpannen.jpg

nergens in de huidige code, templates, data of static directory wordt gebruikt,
dan betreft dit waarschijnlijk een oude/stale URL die Ahrefs nog kent.

In dat geval:

- maak GEEN redirect;
- voeg GEEN dummy-afbeelding toe;
- maak GEEN nieuwe route;
- laat de 404 bestaan;
- rapporteer dat geen actie nodig is.

3. DJANGO DEBUG-INSTELLING
==================================================

Controleer hoe DEBUG in settings.py wordt bepaald.

Productie op Render moet altijd draaien met:

DEBUG = False

Controleer:

- settings.py
- eventuele production settings
- environment variables
- os.getenv / environ helpers
- Render-specifieke configuratie
- .env.example
- deployment-configuratie

LET OP

Zet DEBUG niet simpelweg hardcoded op False als de applicatie lokaal DEBUG=True
nodig heeft.

Gebruik indien nodig een veilige environment-based configuratie, bijvoorbeeld:

DEBUG = os.getenv("DEBUG", "False").lower() in ("true", "1", "yes", "on")

maar alleen als dat past bij de bestaande configuratiestijl van het project.

Productie moet standaard False zijn als de environment variable ontbreekt.

Controleer ook dat:

ALLOWED_HOSTS

correct staat voor:

leefnatuurlijkengezond.nl
www.leefnatuurlijkengezond.nl

zonder onnodig '*' te gebruiken, tenzij daar al een expliciete technische reden voor is.

Rapporteer hoe DEBUG in productie momenteel wordt bepaald.
