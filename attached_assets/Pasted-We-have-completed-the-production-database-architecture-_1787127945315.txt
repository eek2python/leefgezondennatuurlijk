We have completed the production database architecture audit for the Django website **Leef Natuurlijk & Gezond**.

The audit concluded that the repository should first be prepared for PostgreSQL before any Render PostgreSQL database is created or connected.

## Current situation

The current Django configuration hardcodes SQLite:

```python
DATABASES = {
    "default": {
        "ENGINE": "django.db.backends.sqlite3",
        "NAME": BASE_DIR / "db.sqlite3",
    }
}
```

Important findings from the audit:

* Production currently uses filesystem SQLite.
* Render does not appear to have a Persistent Disk.
* `DATABASE_URL` is currently ignored by Django.
* `psycopg2-binary==2.9.10` is already installed.
* `dj-database-url` is not installed.
* Replit currently exposes a `DATABASE_URL` environment variable even though Django ignores it.
* Local development currently uses SQLite.
* `AffiliateProductState` can be seeded deterministically with:

```bash
python manage.py sync_affiliate_product_states
```

* The production `AffiliateProductState` table currently contains 0 records.
* No repository-specific PostgreSQL incompatibilities were found.
* Production PostgreSQL must **not** be created or connected during this task.

## Objective

Prepare the repository so it is safely capable of using:

```text
Production:
Django → Render PostgreSQL

Development/Replit:
Django → SQLite
```

This is a **repository preparation task only**.

Do NOT:

* deploy to Render;
* create a Render PostgreSQL database;
* change Render environment variables;
* change production configuration;
* run production migrations;
* copy any database data;
* restart the Render service;
* modify production data;
* automatically deploy after completing the task.

# Phase 1 — Implement explicit database selection

Refactor the Django database configuration so database selection is explicit and deterministic.

Use these environment concepts:

```text
DJANGO_ENV
DJANGO_DB_BACKEND
DATABASE_URL
```

Desired behavior:

## Development / Replit

Default development behavior must remain SQLite.

For example:

```text
DJANGO_ENV=development
DJANGO_DB_BACKEND=sqlite
```

must use:

```python
django.db.backends.sqlite3
```

with:

```python
BASE_DIR / "db.sqlite3"
```

This is important because the Replit environment currently contains a `DATABASE_URL`.

A stray or automatically injected `DATABASE_URL` must therefore **not silently switch Replit development from SQLite to PostgreSQL**.

## Production

Production must require PostgreSQL.

For example:

```text
DJANGO_ENV=production
DJANGO_DB_BACKEND=postgres
DATABASE_URL=<valid PostgreSQL URL>
```

Production must:

* use `DATABASE_URL`;
* use the PostgreSQL Django backend;
* fail clearly if `DATABASE_URL` is missing;
* fail clearly if `DATABASE_URL` is malformed;
* never silently fall back to SQLite.

A production configuration such as:

```text
DJANGO_ENV=production
```

without a valid PostgreSQL database configuration must raise:

```python
django.core.exceptions.ImproperlyConfigured
```

or an equivalent clear startup configuration error.

# Phase 3 — Implement production-safe PostgreSQL configuration

Use `dj-database-url` to parse `DATABASE_URL`.

The configuration should support:

* reasonable connection reuse;
* connection health checking if supported by the installed Django/dj-database-url versions;
* SSL in production where required for Render PostgreSQL;
* clear configuration errors;
* local SQLite development.

Prefer something architecturally equivalent to:

```python
DJANGO_ENV = os.getenv("DJANGO_ENV", "development").lower()
DJANGO_DB_BACKEND = os.getenv("DJANGO_DB_BACKEND", "sqlite").lower()
DATABASE_URL = os.getenv("DATABASE_URL")

if DJANGO_ENV == "production":
    if DJANGO_DB_BACKEND != "postgres":
        raise ImproperlyConfigured(
            "Production must use PostgreSQL."
        )

    if not DATABASE_URL:
        raise ImproperlyConfigured(
            "DATABASE_URL must be configured in production."
        )

    # parse DATABASE_URL safely

elif DJANGO_DB_BACKEND == "postgres":
    if not DATABASE_URL:
        raise ImproperlyConfigured(
            "DATABASE_URL is required when PostgreSQL is selected."
        )

    # PostgreSQL configuration

elif DJANGO_DB_BACKEND == "sqlite":
    DATABASES = {
        "default": {
            "ENGINE": "django.db.backends.sqlite3",
            "NAME": BASE_DIR / "db.sqlite3",
        }
    }

else:
    raise ImproperlyConfigured(
        f"Unsupported DJANGO_DB_BACKEND: {DJANGO_DB_BACKEND}"
    )
```

This is illustrative, not mandatory.

Implement the cleanest version consistent with the existing settings architecture.

Do not duplicate configuration unnecessarily.
