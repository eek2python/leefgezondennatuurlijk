Automatiseer projectbreed de bepaling van `price_range` op basis van het
numerieke `price`-veld.

Doel:

- `price` blijft de interne numerieke bron voor prijsgerelateerde logica;
- `price_range` wordt centraal en consequent uit `price` afgeleid;
- variantprijzen krijgen hun eigen prijsniveau;
- handmatig verouderde of inconsistente `price_range`-waarden worden niet
  meer leidend gebruikt;
- productkaarten en vergelijkingstabellen tonen uitsluitend het prijsniveau;
- deze taak maakt geen concrete prijzen zichtbaar op de website;
- Product JSON-LD wordt niet automatisch uitgebreid met concrete prijzen;
- productdata, prijzen, rankings, awards en affiliate-links worden niet
  inhoudelijk gewijzigd.

Voor keramische koekenpannen gelden voorlopig deze prijsniveaus:

- minder dan €25: `€`
- €25 tot minder dan €50: `€€`
- €50 tot minder dan €90: `€€€`
- €90 of hoger: `€€€€`

==================================================
2. CENTRALE PRIJSNIVEAUHELPER
==================================================

Maak of gebruik één centrale helper voor de prijsniveaubepaling.

Plaats deze in een bestaande geschikte helpermodule, bijvoorbeeld:

- `utils/pricing.py`;
- `utils/product_helpers.py`;
- of een bestaande categorieconfiguratiemodule.

Gebruik bijvoorbeeld:

from decimal import Decimal, InvalidOperation

def get_price_range(price):
    if price is None:
        return None

    try:
        normalized_price = Decimal(str(price))
    except (InvalidOperation, TypeError, ValueError):
        return None

    if normalized_price < Decimal("0"):
        return None
    if normalized_price < Decimal("25"):
        return "€"
    if normalized_price < Decimal("50"):
        return "€€"
    if normalized_price < Decimal("90"):
        return "€€€"
    return "€€€€"

Gebruik bestaande projectconventies wanneer die afwijken.

Vereisten:

- `None` geeft `None`;
- ongeldige prijzen geven `None`;
- negatieve prijzen geven `None`;
- grenswaarden worden exact verwerkt;
- gebruik bij voorkeur `Decimal`;
- documenteer de grenswaarden;
- geef alleen een prijsniveau terug en nooit een zichtbare concrete prijs.

==================================================
3. ÉÉN BRON VAN WAARHEID
==================================================

`price` is de numerieke bronwaarde.

`price_range` is uitsluitend een afgeleide presentatiewaarde.

Voorkom logica waarbij:

- `price_range` wordt gebruikt om een concrete prijs te bepalen;
- een handmatig `price_range` een berekend niveau overschrijft;
- een productniveauprijsniveau wordt gebruikt voor een variant met een andere
  prijs;
- een prijs van variant A wordt gecombineerd met het prijsniveau van variant B;
- een geformatteerde prijsstring wordt gebruikt voor berekeningen;
- een concrete prijs uit `price_range` wordt afgeleid.

De richting is uitsluitend:

`price` → `price_range`

Nooit:

`price_range` → `price`

==================================================
4. GEEN CONCRETE PRIJSWEERGAVE TOEVOEGEN
==================================================

Deze taak mag geen concrete productprijzen zichtbaar maken op de website.

Het numerieke `price`-veld wordt uitsluitend intern gebruikt voor:

- het berekenen van `price_range`;
- audits en validatie;
- variantconsistentie;
- interne controles;
- toekomstige affiliate- of product-API-integratie.

Op productkaarten en in vergelijkingstabellen mag alleen het prijsniveau worden
getoond:

- €
- €€
- €€€
- €€€€

Niet zichtbaar toevoegen:

- €42,99;
- €59,90;
- vanaf €42,99;
- prijs gecontroleerd op een bepaalde datum;
- actuele prijs;
- adviesprijs;
- kortingsprijs;
- variantprijs;
- prijsrange in eurobedragen.

Voeg geen nieuwe concrete prijscomponent toe.

Activeer geen bestaande verborgen concrete-prijsweergave.

Wijzig geen knoptekst naar een exacte prijs.

Bestaande knoppen mogen bijvoorbeeld blijven:

- Bekijk prijs;
- Bekijk actuele prijs;
- Bekijk prijs en reviews.

Controleer na wijziging alle aangepaste templates en bevestig dat zij
uitsluitend `price_range` of `display_price_range` tonen.

==================================================
5. PRODUCTEN ZONDER VARIANTEN
==================================================

Voor producten zonder varianten:

resolved_price = product.get("price")
resolved_price_range = get_price_range(resolved_price)

Bereid de afgeleide waarde server-side voor.

Bijvoorbeeld:

prepared_product["display_price_range"] = get_price_range(
    product.get("price")
)

Gebruik geen concrete zichtbare prijs in het prepared display-object wanneer
dat niet al bewust onderdeel van de frontend is.

Voorkom mutatie van de oorspronkelijke productdata.

Bij voorkeur:

prepared_product = {
    **product,
    "display_price_range": get_price_range(product.get("price")),
}

Niet:

product["price_range"] = ...

wanneer dat de brondata in-place wijzigt.

==================================================
6. PRODUCTEN MET VARIANTEN
==================================================

Voor producten met varianten:

- gebruik uitsluitend de prijs van de geselecteerde displayvariant;
- bereken `price_range` uit die variantprijs;
- gebruik geen productniveauprijs als fallback;
- gebruik geen prijs van een andere variant;
- laat het prijsniveau leeg wanneer de displayvariant geen prijs heeft;
- wis een oud prijsniveau wanneer een nieuwe variant geen geldige prijs heeft.

Bijvoorbeeld:

display_variant = resolve_display_variant(...)

resolved_price = (
    display_variant.get("price")
    if display_variant is not None
    else None
)

resolved_price_range = get_price_range(resolved_price)

Voor GreenPan Mayflower moet dit opleveren:

- Blauw, interne prijs 42.99 → zichtbaar prijsniveau `€€`;
- Grijs, interne prijs 59.90 → zichtbaar prijsniveau `€€€`.

Voor Kochstar:

- Zwart, interne prijs 13.99 → zichtbaar prijsniveau `€`;
- Taupe, interne prijs 14.99 → zichtbaar prijsniveau `€`.

De concrete prijzen blijven intern en worden door deze taak niet zichtbaar
gemaakt.

10. CLIENT-SIDE VARIANTWISSEL
==================================================

De variantwissel moet het prijsniveau expliciet bijwerken.

Gewenst patroon:

if (variant.price_range) {
    priceRangeElement.textContent = variant.price_range;
    priceRangeElement.hidden = false;
} else {
    priceRangeElement.textContent = "";
    priceRangeElement.hidden = true;
}

Niet:

    priceRangeElement.textContent = variant.price_range;
}

zonder `else`, omdat dan een oud prijsniveau kan blijven staan.

Voeg geen JavaScript toe dat concrete prijzen formatteert of toont.

Voeg geen code toe zoals:

priceElement.textContent = `€ ${variant.price}`;
